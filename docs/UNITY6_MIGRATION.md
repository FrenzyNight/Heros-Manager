# Unity 6000.4.7f1 이식

## 기준

- 원본: Unity 2019.4.13f1, URP 7.3.1.
- 대상: 로컬 설치 Unity 6000.4.7f1 (`f3c3c4248748`).
- 기존 패키지를 설치 에디터 동봉 버전에 맞춤: URP 17.4.0, uGUI 2.0.0, Test Framework 1.6.0, Timeline 1.8.12, Rider 3.0.40.
- TextMeshPro는 uGUI 통합 버전을 사용하며 구형 별도 패키지 핀을 제거했습니다.
- 영웅 상태 텍스트가 사각형으로 렌더링되는 문제는 구형 TMP 셰이더의 정점 UV 형식 불일치였습니다. 설치된 uGUI의 `TMP Essential Resources.unitypackage`에서 기존 셰이더·include 17개를 갱신하고 `.meta` GUID와 폰트·설정은 보존했습니다.
- 구형 Collaborate/VS Code 통합 패키지를 제거했습니다. 엔진이 자동 추가한 별도 기능 패키지는 제거하여 범위를 유지했습니다.
- 입력은 기존 Legacy Input Manager를 유지합니다.
- Unity API Updater가 기존 DOTween Pro 에디터 DLL과 Skybox 에디터 API를 변환했습니다.
- URP 전역 설정과 기본 볼륨, 엔진 설정·일부 임포터 메타는 Unity가 생성/업그레이드합니다.
- 빌드에 포함된 4개 씬과 URP 에셋을 최신 형식으로 저장했습니다. 구형 씬의 자동 베이크가 플레이 중 호출되는 오류를 막기 위해 씬 로드 시 베이크를 비활성화했습니다.
- 이미지 폴더 메타 2개에 원래 남아 있던 병합 충돌 마커를 해소했습니다.

설정 근거는 설치 에디터의 `Editor/Data/Resources/PackageManager`에 포함된 패키지 manifest와
[Unity 업그레이드 가이드](https://docs.unity.com/en-us/engine/6000.0/manual/upgrade-guides),
[Unity 6.4 업그레이드 가이드](https://docs.unity.com/en-us/engine/6000.6/manual/upgrade-guides/upgrade-guide-unity64)입니다.

## 코드 변경

- 싱글톤 중복 초기화·정상 인스턴스 오삭제·씬 재진입 불가를 수정했습니다.
- 24개 테이블의 반복 로더를 공통 제네릭 로더로 통합했습니다. JSON 공백/BOM, 빈 테이블 형식, 중복 ID를 검사합니다.
- 저장 I/O와 게임 상태를 분리하고 원자적 교체·백업·손상 복구·기존 파일 호환을 추가했습니다.
- 아이템/영웅 상태 저장·복원과 이어하기, 덮어쓰기 확인을 연결했습니다.
- 플레이 초기화 순서와 직접 인게임 실행, 타이틀 복귀 시 시간 배율을 정리했습니다.
- 15개 미니게임 매니저의 다형적 초기화·중복 생성·코루틴·생성물 정리를 공통화했습니다.
- 미니게임 보상 중복 지급을 막고 포털 재전환 초기화와 후보 검증을 추가했습니다.
- 튜토리얼의 마지막 대사 누락, 범위 초과, 페이지 이동과 시계 복원을 수정했습니다.

## 재실행 가능한 검사

`tools/Validate-Unity.ps1`의 Project/Save/Play/Build 모드를 사용합니다. 동일 프로젝트의 Unity 에디터는 먼저 닫습니다.

- Project: 정확한 에디터 버전, 게임 테이블과 스테이지 참조, 활성 빌드 씬의 누락 스크립트.
- Save: 임시 폴더에서 저장 라운드트립, 백업, 손상 파일·데이터, 쓰기 실패, 옵션 기본값/범위.
- Play: 타이틀·인트로·인게임 및 인게임 재진입, 타이틀 시간 배율, 미니게임 중복 보상.
- Build: 활성 빌드 씬을 포함한 Windows x64 일반 빌드.

## 남은 게임 개발 범위

이번 작업은 기존 게임의 이식과 공통 코드 구조개편입니다. 모든 게임 콘텐츠가 완성된 상태를 뜻하지 않습니다.

- Stage2/3 일부 미니게임의 빈 시작/보상 함수와 미연결 콘텐츠.
- 전용 엔딩 연출 및 완료 상태 저장. 현재 마지막 스테이지 완료 시 잘못된 다음 스테이지로 넘어가지 않고 정지합니다.
- 도감 메뉴, 전체 게임 진행 밸런스, 장시간 플레이/모든 미니게임 조작 검수.
- 포털 전환 주기 원본 데이터가 없어 Inspector 기본값 15초를 사용합니다. 기획 확정 후 조정해야 합니다.
- 원본 FBX의 일부 자기교차 폴리곤, 오래된 에셋 셰이더 경고는 아트 검수가 필요합니다.
- 저장은 일 경계 상태 중심이며 캠프 타이머·부적 등 모든 진행 상태를 포괄하지 않습니다.
- Windows 외 플랫폼의 빌드와 원자적 파일 교체는 별도 검증이 필요합니다.

## 실행 검증 결과

2026-11-05, 로컬 Unity 6000.4.7f1 / Windows에서 확인했습니다.

- Project: 종료 코드 0. 24개 테이블 로딩, 3개 스테이지 및 55개 미니게임 행, 활성 씬 4개의 누락 스크립트 검사 통과.
- Save: 종료 코드 0. 임시 디렉터리에서 저장 회귀 검사 전체 통과.
- Play: 종료 코드 0, `PLAY SMOKE PASSED: 0 errors`. 타이틀 → 인트로 → 인게임 → 타이틀 → 인게임 재진입, 시간 배율 복원, 미니게임 보상 1회 지급을 확인했습니다. 전체 콘텐츠를 조작한 테스트는 아닙니다.
- Build: 종료 코드 0, `WINDOWS BUILD PASSED`. 4개 씬을 포함한 Windows x64 Mono 일반 빌드를 생성했습니다. 실행 파일은 `HerosManager/Builds/Windows/HerosManager.exe`이며 배포 시 같은 디렉터리의 DLL 및 데이터 폴더도 함께 필요합니다.
- 실행 파일 화면 검수: 타이틀 메뉴, 이어하기의 인게임 진입, 첫 튜토리얼 대사, 수정된 영웅 상태 한글·숫자 렌더링을 확인했습니다. 개발 빌드 실행 시 OS가 네트워크 권한을 요청했으나 변경하지 않았으며, 최종 일반 빌드는 해당 요청 없이 검수했습니다.

배치 플레이 검증 중 Unity Editor Search 인덱스 초기화에서 `ArgumentOutOfRangeException`이 발생했습니다. 로컬 `UserSettings/Search.settings`에 `indexOnEditorStartup: false`를 적용한 뒤 통과했습니다. 이는 게임 코드 수정과 별개의 로컬 에디터 설정이며 Git에 포함하지 않습니다. 새 환경에서 동일 현상이 있으면 에디터 Preferences의 Search에서 **Index on Editor startup**을 끄고 재실행합니다.

검증 로그와 빌드 산출물은 생성 파일이므로 Git에 포함하지 않습니다. 기존 외부 에셋의 deprecated API 및 원본 모델 임포트 경고는 남아 있습니다.
