# 초원·사막 8일 플레이

## 플레이 범위

새 게임은 Title → Intro → 초원 1일로 시작한다. 매일 보급 준비, 원정과 채집, 귀환, 야간 캠프 관리, 결산을 거쳐 진행한다. 하루는 게임 시간 240초이며 78초에 원정대가 돌아온다. 튜토리얼·도움말·일시정지는 시계와 캠프 작업을 함께 멈춘다.

- 4일째 원정을 성공하고 활동 가능한 용사가 남으면 승리한다.
- 전원 체력 0 또는 마지막 날 원정 실패는 패배다. 체력 0 용사는 출전하거나 회복할 수 없다.
- 결산에서 다음 날로 이동하며 아침 상태를 저장한다. 중간 종료 시 해당 날짜의 아침부터 재개한다.
- 승패 결과도 저장한다. 이어하기로 완료된 날을 반복하여 보상을 얻을 수 없다. 결과 화면의 새 원정은 저장 성공 후 1일부터 시작한다.
- 초원 승리 화면의 ‘사막으로 이어가기’로 사막 1일에 진입한다. 사막까지 8일이 현재 플레이 범위이며 마법 숲은 아직 열리지 않는다.

## 사막 4일과 성장 계승

초원 완료 체크포인트를 분리 복제해 사막 1일 저장에 성공한 후 장면을 전환한다. 기존 초원 완료 저장도 같은 버튼으로 이어갈 수 있다. 전투력·용사도·아이템·울타리·남은 이벤트 큐를 보존한다. 이동 보급은 물 12, 고기 12, 음식 6, 원석 3이며 생존 용사만 체력 30을 회복한다(최대 100). 사막 저장을 다시 읽거나 버튼을 반복 호출해도 보급을 중복 지급하지 않는다. 저장 실패 시 초원 기록과 현재 화면을 유지한다.

| 사막 날짜 | 진행 목표 | 최소 고기 / 물 | 순탄 점수 |
| --- | --- | --- | --- |
| 1일 | 오아시스 길 찾기, 다음 날 물 확보 | 9 / 9 | 850 |
| 2일 | 유적 보급로 개척, 원석·약초 확보 | 10 / 10 | 900 |
| 3일 | 모래바람 돌파, 마지막 날 요리 준비 | 11 / 11 | 950 |
| 4일 | 사막 횡단 성공 | 12 / 12 | 1050 |

날짜별 목표는 운영 안내이며 별도 퀘스트 보상은 없다. 사막도 매일 결산을 확인하고 다음 날로 이동하며, 마지막 날 성공과 생존자가 필요하다. 사막 승패는 제목 화면에서 이어하기로 복원된다. 마법 숲 자동 진입 대신 완료 화면에서 현재 개발 범위를 안내한다.

성장 규칙은 초원과 같다. 성공 용사도 최소 10, 대성공 최소 15, 용사도 25마다 전투력 15 증가. 초원 일반 성공 4회 → 사막 일반 성공 4회이면 용사별 용사도 40 → 80, 레벨 2 → 4, 전투력 135 → 185가 된다. 생존자 4명·스트레스 0·최소 고기/물·음식 6 기준 사막 여정 점수는 915/1020/1065/1110으로 순탄 기준을 넘는다. 부상·사망·스트레스는 별도 관리해야 하며 추가 보급으로 점수를 보완한다. 생존자가 적다고 자동으로 난이도를 낮추지는 않는다.

유적은 벌목과 미로, 들판은 약초와 사냥, 호수는 낚시와 물긷기를 제공한다. 미로 보물마다 약초 2·원석 1을 임시 장부에 적립하고 채집 종료 시 지급한다. 벌목은 일반 60%·황금 10%·벌레 30%다. 오아시스는 매일 게임 시간 기준으로 잠깐 열리며 물·고기·나무를 보충한다. 진행에 오아시스 방문은 필수가 아니다. 키보드·마우스와 패드 조작을 각각 안내하며 채집 재입장 때 생산 루프와 캐릭터 상태를 초기화한다.

`MeadowCampaign`과 저장 필드 `meadowOutcome`은 직렬화·기존 호출 호환성을 위해 이름을 유지하되 현재 지역(초원 또는 사막)의 결산·결과를 의미한다. `CampaignProgressionRules`는 지역 전환과 1회 보급을 담당한다.

사막 통합 검증: `./tools/Validate-Unity.ps1 -Check Desert`. 검증은 격리 저장소에서 실제 장면·버튼·채집 보상 콜백·가상 패드 입력·4일 경계·승패 재개를 확인한다. 보급 콜백과 시간 가속을 사용하므로 사람의 채집 숙련도나 실제 16분 운영 난이도를 대신 평가하지는 않는다.

2026-11-05 사막 확장 후 `Rules`, `Save`, `Project`, `Play`, `Meadow`, `Desert`, `Isolation`, `IsolationPlay`, `Build`를 통과했다. 이후 초원 셰이더 변경은 `Lighting`과 `Build`로 추가 검증했다. 사막의 실제 플레이 체감 난이도와 물리 패드 검증은 별도로 필요하다.

## 첫 원정 실습과 안내

새 원정의 첫날에는 설명창 대신 실제 행동을 확인하는 실습 카드가 나타난다. 최소 고기·물 보급 → 출정 → 채집 창 → 숲에서 나무 15개 → 보상 수령 후 캠프 복귀 → 모닥불까지 이동 → 불 피우기 → 요리 → 음식 수령의 9단계다. 현재 작업 위치와 버튼을 민트색 테두리로 표시하며, 벌목에서는 현재 홈 방향도 알려 준다.

실습 동안 하루 시계만 정지한다. 이동과 채집·조리는 계속 실행되고 실제 자원을 사용한다. 불의 소진과 완성 음식의 부패는 보호하지만, 재료나 보상을 자동 지급하지 않는다. 잘못된 구역이나 재료 부족은 다시 채집하여 해결할 수 있다. 요리 시간 40초와 비용은 일반 플레이와 같다.

실습 카드는 접거나 실습을 건너뛸 수 있다. 완료·건너뛰기는 아침 저장의 `onboardingComplete`만 갱신하며 진행 중 자원을 체크포인트에 섞지 않는다. 이어하기에서는 완료한 실습을 다시 강제하지 않는다. 이후 ‘플레이 안내’를 펼치면 채집 구역·빨래·울타리·이벤트별 조작과 목적을 볼 수 있다.

캠프에서는 왼쪽 카드, 채집 장소 선택과 미니게임에서는 상단 가로 안내를 사용해 실제 조작 영역과 장소 이름을 가리지 않는다. 기존 조작 설명은 안내를 접으면 다시 보인다.

안내를 접어도 현재 단계와 목표 테두리는 유지된다. 보급량·벌목·조리 진행에 따라 실습 진행률이 부드럽게 채워지고, 잘못된 벌목 입력에는 회복 대기를 안내한다. 요리 중 채집에 나가도 완성되면 캠프 복귀를 안내하며, 일반 플레이에서는 수령 제한 시간도 표시한다. 실습이 끝나면 시간 재개를 알리고 현재 보유량과 다음 날 테이블의 최소 보급량을 비교한다. 밤에 불이 꺼진 경우 점화를 우선 안내한다. 카드 위 클릭은 뒤쪽 UI나 캠프 이동으로 전달하지 않는다.

대사는 초당 54글자를 기준으로 프레임 누적 시간에 따라 출력하며 문장부호 뒤에 짧게 쉰다. 클릭·Space·Enter·패드 A를 누르면 출력 중인 문장이 즉시 완성되고 다음 입력에서 다음 대사로 진행한다. 타이핑음은 재생 중 매 글자마다 다시 시작하지 않는다.

## 보급·성장·회복 규칙

| 규칙 | 효과 |
| --- | --- |
| 최소 고기·물 충족 + 원정 평가 순탄 | 실패 확률 0%, 대성공/성공 비율은 기존 가중치 정규화 |
| 초원 성공/대성공 | 용사도 최소 +10/+15 |
| 누적 용사도 25 | 레벨 +1, 전투력 +15; 저장 복원 시 중복 적용하지 않음 |
| 초원 실패 | 체력 최소 -40, 전투력·용사도 증가 없음 |
| 약초 2 + 고기 2 + 물 2 | 모닥불에서 40초 조리하여 음식 3개; 수령 제한은 기존 20초 |
| 출정 보급 음식 1개 | 귀환 생존 용사 전원 체력 +2, 최대 +12; 치명상을 되돌리지는 않음 |
| 동굴 원석 | 미니게임 세션 종료 때 한 번 지급, 일일 저장에 포함 |
| 원석 3개 | 준비 중 또는 귀환 후 생존 용사 전원 체력 +20; 전원 최대 체력이면 구매 불가 |

원석 보상은 기존 `game1cage_jem.GetJemAmount`를 사용한다. 부적 전체 구현과는 별개인 초원 회복 용도다. 기존 5자원 저장 배열의 순서는 바꾸지 않았다.

수치상 가능한 운영 예시는 1~3일 밤 요리 2회로 음식 6개를 다음 날 보급하는 것이다. 모닥불을 유지하고 일반 성공을 이어가면, 빨래를 생략해도 2~4일 원정 점수는 680/725/830으로 순탄 기준 650/700/800을 넘는다. 습격을 제외한 전체 추가 채집량은 고기 28·물 30·약초 2·나무 120이다. 이는 조작 속도를 실측한 결과가 아닌 테이블·규칙 계산이다.

습격은 별도 예산이다. 최대 손실에 대비하려면 하루 종료 시 생고기·물을 각각 다음 날 최소량+20까지 비축하거나 울타리에 투자해야 한다. 음식은 기존 습격 대상에 포함되지 않는다. 밤에 불을 계속 방치하면 용사당 약 +48 스트레스가 발생하므로 음식만으로 모닥불을 대체할 수는 없다.

## 게임패드

새 패키지 없이 Windows XInput 어댑터를 사용한다. Xbox/XInput 호환 패드가 대상이며, 비 XInput 기기와 다른 OS의 패드 지원은 보장하지 않는다. 키보드·마우스 입력은 유지한다.

| 화면/작업 | 조작 |
| --- | --- |
| 메뉴·보급·결산 | 왼쪽 스틱/십자키 이동, A 선택, B 뒤로, Start 일시정지 |
| 캠프 이동·작업 | 오른쪽 스틱 이동, 작업 장소 근처에서 왼쪽 스틱/십자키로 버튼 선택 후 A |
| 옵션 슬라이더 | 좌우 조절 |
| 벌목 / 약초 | 왼쪽 스틱 또는 십자키 방향 |
| 동굴 | A 점프, X 누르고 숙이기 |
| 사냥 | 오른쪽 스틱 조준, RT 발사 |
| 낚시 | LB 통나무 방향 전환 |
| 물 채집 | 오른쪽 스틱 좌우 또는 십자키 좌우 |
| 빨래 | 얼룩 선택 후 A, 헹굼 LB/RB 교대, 말리기는 표시된 버튼 누르기 |

연결 시 조작 도움과 선택 강조를 표시한다. 옵션의 패드 진동 설정을 저장한다. 연결 해제 시 일시정지하고, 포커스 상실·분리·일시정지·종료 시 모터를 정지한다. 재연결 후 입력을 한 번 놓아야 새 화면을 조작할 수 있다.

## 검증 방법과 범위

`tools/Validate-Unity.ps1`의 `Rules`, `Save`, `Isolation`, `IsolationPlay`, `Project`, `Play`, `Meadow`, `Guide`, `Lighting`, `Build`를 사용한다. 저장 격리와 검증 종료 처리는 `ARCHITECTURE.md`의 ‘검증 저장의 안전 경계’를 따른다.

## 미니게임 아트

초원·사막의 플레이 가능한 미니게임 13종에 사용하는 이미지 215개를 캠프의 로우폴리 분위기와 맞춘 부드러운 면 기반 일러스트로 교체했다. 배경·캐릭터·동물·꽃·물고기·원석·작업 소품을 포함하며, 일반/황금 보상 구분과 기존 동작 방향·프레임 순서를 유지한다. 미완성 3단계 전용 이미지와 타이머·그림자·낚싯줄 같은 보조 텍스처는 이번 교체 범위에 포함하지 않는다.

실제 적용 PNG는 `HerosManager/Assets/04.Images/MiniGame`에 있다. 기존 `.meta` GUID, 스프라이트 ID와 피벗을 보존하고, 배경·타일 29개는 원본의 4배, 전경·동작 이미지 186개는 2배 해상도를 사용한다. PPU와 다중 스프라이트 사각형도 같은 비율로 조정하여 기존 배치 크기를 유지한다. 이미지 필터는 Bilinear이며 텍스처 압축은 사용하지 않는다. 애니메이션 클립과 충돌 판정은 변경하지 않았다. 미로 벽에는 석재 이미지를 연결하고 길을 모래색으로 바꿨으며, 미로·오아시스 캐릭터와 물 채집의 보조 이미지 참조를 기존 쿠키 캐릭터 시트에서 프로젝트 캐릭터·양동이로 바꿨다.

`Art/MinigameRefresh`에 내장 `image_gen`으로 제작한 원본 아틀라스 18장, 기존 이미지 참조 시트, `manifest.json`, 전체 생성 프롬프트 `prompts.json`과 동굴 보정 프롬프트 `revisions.json`을 보관한다. 재적용하려면 Windows PowerShell 7에서 `tools/Prepare-MiniGameArt.ps1`, `tools/Apply-MiniGameArt.ps1` 순서로 실행한다. Prepare는 Git 기준 리비전 `b55f8231c2effd41a50eb70ce289f74c9488fffe`에서 원본을 `Logs/art-review/originals`에 확보한다. Apply는 원본 해시·GUID를 확인하고 아틀라스를 분할한 뒤 해상도·알파 영역·메타데이터를 적용한다. 두 명령은 이미지를 다시 생성하는 API 호출을 하지 않는다.

`tools/Validate-Unity.ps1 -Check Art`는 격리된 저장으로 실제 Title/InGame 씬과 7개 지역 패널을 열어 13종 미니게임의 활성화, 스프라이트·애니메이션 참조를 검사한다. 각 지역의 초기/후기 화면 14장을 `Logs/art-after`에 저장한다. 사람의 조작, 전체 애니메이션의 자연스러움이나 GPU 성능을 측정하는 검사는 아니다. 일반 저장 파일 목록·해시·수정 시간은 공통 검증 세션에서 보호한다.

## 숲 캠프의 조명

초원의 지형·나무·바위에는 `MeadowSurfaceTreatment`가 장면 전용 머티리얼을 적용한다. `Resources/Shaders/MeadowSurface.shader`는 기존 팔레트와 로우폴리 면을 유지하면서 지면의 완만한 색 변화, 녹색 잎의 약한 역광 투과, 낮은 표면 광택을 더한다. URP 그림자·깊이·노멀 패스를 제공하며 시계의 햇빛·달빛과 모닥불을 따른다. 공유 머티리얼 에셋은 수정하지 않으며 비활성화 시 원본을 복원한다. 사막에는 적용하지 않는다. `Lighting` 검증은 셰이더 오류, 적용 범위와 재활성화 후 원본 복원을 함께 확인한다.

2026-11-05 초원 셰이더 적용 후 `Lighting`과 Windows `Build`를 통과했다. 낮·석양·점화 후 캡처를 확인했으며, 두 검증에서 보호된 저장 파일 목록·SHA256·수정 시간이 동일했다. 프레임 시간 및 GPU별 성능 측정은 수행하지 않았다.

`LightController`는 게임 시계를 따라 낮의 따뜻한 햇빛에서 석양과 푸른 달빛으로 전환한다. 하늘·수평·지면 주변광을 나눠 캐릭터와 오브젝트의 면을 구분하고, 먼 숲에 옅은 안개를 적용한다. 모닥불의 기존 Point Light를 지면 위로 올려 따뜻한 광원이 주변 바닥과 소품을 비추게 한다. 불빛의 작은 흔들림은 일시정지 시 함께 멈추고, 기존 점화·소화·다음 날 초기화에 연동한다.

`InGameLighting.asset`은 Neutral 톤 매핑과 절제한 채도 보정을 보관하며 메인 카메라에서 적용한다. URP의 HDR·4× MSAA·소프트 그림자와 낮은 강도의 접촉 음영(SSAO)을 사용한다. 기존 Screen Space Overlay UI는 색 보정 대상에 포함되지 않는다. 렌더링 비용은 이전보다 증가하므로 저사양 PC의 프레임률은 별도로 확인해야 한다.

수치를 다시 적용하려면 에디터의 `Tools > Heros Manager > Apply Forest Lighting Art Direction`을 사용한다. 이 명령은 InGame 씬과 렌더링 에셋을 저장하므로 편집 중인 씬을 먼저 저장한다. 자동 임포트나 플레이 시작 시 에셋을 수정하지 않는다.

2026-11-05 조명 변경 후 `Lighting`, `Project`, `Play`, `Build`를 통과했다. 에디터의 실제 카메라 렌더링 경로에서 5개 시점의 화면을 확인했다. `Play` 검증도 자체 임시 저장 디렉터리를 사용하도록 보완했으며, 재검사 전후 일반 저장 파일의 해시와 수정 시간이 동일함을 확인했다.
